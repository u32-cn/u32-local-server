# 访问规则授权（u32-ls access）

**新增**访问规则的唯一写入口是一个临时浏览器确认页。AI 只能请求弹窗，不能程序化写配置。**删除**允许规则在 `/config` 页直接操作（收紧权限，无需弹窗）。

## AI 行为约束

> **禁止直接编辑 `~/.u32-local-server/config/main.json`，禁止调用任何写配置的 HTTP 接口。需要新增访问规则时，必须执行 `u32-ls access` 打开浏览器确认页，由用户点「允许」后才会写入。**

`/config/api` 的 `add` / `remove` / `setAllowWrite` 已移除（返回 `410 Gone` + 引导）；删除请调用 `removeAllow`。403 路径错误同样给出引导。AI 若需授权目录，只能提示用户执行 `u32-ls access`，不得代改配置。

## 用法

```bash
# 打开授权页，AI 给定的文件夹直接展示给用户确认
u32-ls access D:/data

# 不带路径：页面显示「未选择」，用户点「浏览文件夹…」自行选
u32-ls access
```

命令在 `127.0.0.1` 随机端口起一个一次性服务，探测到 Edge / Chrome 时用 `--new-window` 在**独立新窗口**打开（960×720，不塞进已开浏览器的标签页），探测不到则降级到系统默认浏览器；**主服务未启动也能用**。纯 Node 内置模块，Windows / Linux 同一份代码。

## 页面操作

- **待授权文件夹**：顶部大字显示 AI 给定的路径（或「未选择」）；选「只读」或「读写」（默认只读）
- **允许**：点后立即把该路径写入允许列表并关闭窗口
- **取消**：不写入，直接退出
- **浏览文件夹…**：页面内弹出居中模态框（div 遮罩 + iframe 加载 picker），地址栏 / 后退 / 前进 / 上级 / 点目录进入，选中后点「选择文件夹」经 `postMessage` 回传并回填——**不新开浏览器窗口，不受 allow 列表限制，全程不用手填路径**
- 授权页只显示待授权文件夹与「允许 / 取消 / 浏览」，**不显示任何允许/拒绝列表**；删除在 `/config` 页操作
- 未在 5 分钟内操作：临时服务自动关闭，不写入

临时服务只读接口 `GET /api/ls?path=`（token 校验，仅 127.0.0.1；不受 allow 列表限制，因为授权页正是要给未授权目录授权）。预填目录不存在时自动回退到最近存在的上级并提示。

路径统一按 POSIX 规则规范化（`~/` 展开、Windows 盘符去前导 `/`），去重后落盘；`deny` 优先于 `allow`、allow 空 = 拒绝所有的不变式保持不变。

## 删除允许规则

在 `http://127.0.0.1:<port>/config` 页允许列表点「删除」即删、即时生效。API：`POST /config/api { "action": "removeAllow", "path": "<posix 路径>" }`。删除是收紧权限，不需用户弹窗授权。

拒绝列表（deny）删除仍被禁止（放宽权限），返回 410。

## 与其他入口的关系

- `/config` 页：允许列表可删除、不可新增；拒绝列表只读；MIME 与端口可改
- 首页 / 文件选择器里「403 去加允许列表」的提示，改为引导用户执行 `u32-ls access`
- 配置文件结构不变，见 [config.md](config.md)
