u32 u32-local-server
用途 对比 文档 安装 GitHub v1.6.0

本地 HTTP 服务 · 仅监听 127.0.0.1

让 Web 应用安全地使用本机文件，
让 AI 直接操控你的页面

目录只授权一次，之后页面通过 HTTP 直接读写，不再弹窗；页面接入桥之后，AI 工具可以给它下发指令、同步拿到结构化结果。 两项能力都需要 Web 端按协议做小幅改造。

01

两个核心用途

都要改造 Web 端
本地文件服务

授权一次，之后页面直接用

浏览器自带的 File System Access API 也能读写本地文件，但句柄权限不能跨会话保持：刷新、换标签、隔天再来都要用户重新确认，普通网页无法给一个应用长期备好一组目录。

  • 允许目录写进配置，逐条标只读或读写，deny 优先
  • 页面走 /file/ 读、/api/fs 写，不再弹授权框
  • 自带文件选择器 /picker，打开 / 选目录 / 另存为，嵌 iframe 即用
AI 桥接服务

AI 发指令，页面回包

页面接入 /bridge 后注册，并声明一份 help：这个页面接什么指令、返回什么。AI 通过 /bridge/api/apps 发现它，POST 一条消息，同步等回包。

  • AI 不用理解界面结构，不截图、不猜按钮、不模拟点击
  • 服务器只做透明转发，业务语义由页面自己定义
  • 一条指令至多送达一次，超时 504 由 AI 侧重试
02

和浏览器自带的文件能力比

差在授权模型
File System Access API u32-local-server
授权每次会话都要用户重新确认配置一次，长期有效
多目录逐个授权，无法预置允许列表可写多条，逐条标只读 / 读写
拒绝规则无deny 优先于 allow
文件选择器自己实现/picker 直接嵌入
AI 调用不可，权限绑在用户手势上可通过 /bridge 下发指令
03

其余能力

七条路由
/file/

本地文件访问

直链读取允许目录里的文件，兼容 Windows 盘符与 ~/，自带目录浏览。

/api/fs

文件写入

写入、追加、建目录、删除、移动、复制、查询，共七个动作。

/proxy/

CORS 代理

转发任意 HTTP 请求，补齐 CORS 头，绕过跨域限制。

/bridge

浏览器桥

注册、长轮询、回包，AI 与页面之间的透明转发层。

/status

运行状态

进程与宿主机指标，页面与 JSON 同源，不采集敏感信息。

/config

可视化配置

端口、允许列表、MIME 类型网页上改，即时生效。

快速开始

30 秒
terminal
# 安装
npm install -g u32-local-server

# 启动，默认 127.0.0.1:19527
u32-ls start

# 打开配置页，加一个允许目录
u32-ls open .

默认拒绝所有访问。加允许目录之前什么都读不到，这是设计不是 bug。

只监听本机。不暴露公网；写接口另带同源 Origin 校验，挡住跨站请求。

装在哪。在 AI 工具的托管终端里 npm i -g 可能落到工具自带的 node，装前先看 npm config get prefix。
